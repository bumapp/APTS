### W-043 — reproduction

DONE: The script proves that the /api/Feedbacks/ endpoint has a CORS misconfiguration vulnerability, evidenced by the server responding with 'Access-Control-Allow-Origin: *' header when an arbitrary origin is sent in the request, allowing any website to access sensitive feedback data from users.

```python
import httpx

# Target URL
url = "http://juice-shop:3000/api/Feedbacks/"

# Setting an arbitrary origin header
headers = {
    "Origin": "https://attacker-site.com"
}

try:
    # Make the request
    response = httpx.get(url, headers=headers)
    
    # Check for the vulnerable CORS header
    acao_header = response.headers.get('Access-Control-Allow-Origin')
    
    print(f"Request URL: {url}")
    print(f"Response Status Code: {response.status_code}")
    print(f"Origin Header Sent: {headers['Origin']}")
    print(f"Access-Control-Allow-Origin Header: {acao_header}")
    
    # Confirm the vulnerability
    if acao_header == "*":
        print("\n[CORS MISCONFIGURATION DETECTED]")
        print("The server responds with 'Access-Control-Allow-Origin: *'")
        print("This allows ANY origin to access this endpoint")
        print("Sensitive data may be exposed to malicious websites")
    else:
        print("\nNo CORS misconfiguration detected")
        
except Exception as e:
    print(f"Error making request: {e}")
```

**Fix.** Configure the server to return specific trusted origins in the Access-Control-Allow-Origin header instead of using wildcard (*), and implement proper origin validation.
