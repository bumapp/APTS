Create a normal user with sudo access:
adduser apts-admin
usermod -aG sudo apts-admin
exit 

ssh apts-admin@<host-ip>       # Log back in as the new user
whoami                         # should print: apts-admin
id                             # note the numeric UID — usually 1000, sometimes 1001

Update the OS:
sudo apt-get update
sudo apt-get -y upgrade
Reboot if the kernel or libc was upgraded.

Install the tools we need:
sudo apt-get install -y \
    ca-certificates \
    curl \
    gnupg \
    openssl \
    python3 \
    python3-pip \
    unzip \
    git

Remove any old Docker installation:
for pkg in docker.io docker-doc docker-compose docker-compose-v2 podman-docker containerd runc; do
    sudo apt-get remove -y "$pkg" 2>/dev/null || true
done

Add Docker's official GPG key and apt repo:
sudo install -m 0755 -d /etc/apt/keyrings

sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
    -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
    https://download.docker.com/linux/ubuntu \
    $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
    sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update

Install Docker Engine, CLI, and Compose:
sudo apt-get install -y \
    docker-ce \
    docker-ce-cli \
    containerd.io \
    docker-buildx-plugin \
    docker-compose-plugin

Let apts-admin run Docker without sudo
sudo usermod -aG docker apts-admin

Log out and back in.

Verify Docker works without sudo
docker version              # both Client and Server sections should print
docker compose version      # v2.x
docker run --rm hello-world # downloads and runs, no sudo needed
If hello-world prints its banner without asking for sudo, Docker is ready.

Working directory
mkdir -p ~/apts
cd ~/apts

Transfer the files: 
scp apts-skeleton.zip apts-admin@<host-ip>:~/apts/

Confirm the project files belong to apts-admin (not root)
ls -ld . && ls -l compose-database.yml
Owner should be apts-admin:apts-admin on both. If for any reason they show root root, fix it:
sudo chown -R apts-admin:apts-admin ~/apts

Make the bootstrap scripts executable:
chmod +x generate_certs.sh generate_tokens.py

Generate a strong DB password:
openssl rand -base64 32 | tr -d '=+/' | cut -c1-32 > tokens/db_pass.txt
chmod 600 ~/tokens/db_pass.txt

Generate the TLS certificates:
./generate_certs.sh

Verify one cert has the right SAN:
openssl x509 -in certs/orchestrator.crt -noout -text | grep -A1 "Subject Alt"
# should show: DNS:orchestrator, DNS:localhost

Override the two DB files to postgres's UID 999:
sudo chown 999:999 certs/database.key certs/database.crt
sudo chmod 600 certs/database.key
sudo chmod 644 certs/database.crt

Start the database:
docker compose up -d database
Follow the logs until you see the ready message:
docker compose logs -f database
...
CREATE DATABASE
...
running /docker-entrypoint-initdb.d/00-init.sql
CREATE TABLE
CREATE INDEX
... (five CREATE TABLE lines in total)
...
database system is ready to accept connections

Confirm health:
docker compose ps database

Verify the schema loaded:
docker compose exec -T database psql -U apts -d apts -c "\dt"
Expected — exactly five tables:
 Schema |       Name        | Type  | Owner
--------+-------------------+-------+-------
 public | agent_results     | table | apts
 public | audit_log         | table | apts
 public | engagements       | table | apts
 public | engagement_state  | table | apts
 public | token_hashes      | table | apts

Generate bearer tokens and seed hashes
./generate_tokens.py
Expected output:
==> generating tokens for all components

Confirm the DB and filesystem are in sync — both should show the same 10 components:
ls tokens/*.token | wc -l    # should be 10
docker compose exec -T database psql -U apts -d apts \
    -c "SELECT component FROM token_hashes ORDER BY component;"
